# USDKit's generated entities are invisible to entity queries

**Status:** Observed on macOS 27.0.1. Reported to Apple as **FB25173225** (2026-10-13).
**Workaround in this package:** `SelectionEffectSystem` walks the subtrees of `USDStageComponent` entities every few updates (`Sources/SelectionEffects/QueryHiddenEntities.swift`). Apps can do the same with `Entity.descendants(where:)`.

## Summary

The `ModelEntity`s that `USDStageComponent` generates render and can be reached through `children`. But `Scene.performQuery` doesn't return them, even for `.has(ModelComponent.self)`, and they send no `ComponentEvents`. So systems written the documented way (an `EntityQuery` in `update(context:)`) never see USD content. There's also no public way to map a USD prim to the entity `USDStageComponent` generates for it. (The public `USDPlayer` API's `MeshData` carries a `primPath`, but that's for building your own entities.)

## Environment

- macOS 27.0.1 (26A434), Xcode 27.0 (27A266a), MacBook Pro M1 (MacBookPro17,1)

## Reproduction

[`USDKitQueryRepro/`](USDKitQueryRepro) is a standalone Swift package that uses Apple frameworks only. It loads a two-prim USDA through `USDStageComponent` in a `RealityView`, next to a control `ModelEntity`.

```sh
cd Docs/USDKitQueryRepro
swift run USDKitQueryRepro
```

Output, the same in 3 of 3 runs:

```
render status: completed
ModelComponent entities generated under the stage (via children): 2
  of those, returned by performQuery(.has(ModelComponent.self)): 0
control ModelEntity returned by performQuery: true
stage entity returned by performQuery(.has(USDStageComponent.self)): true
ComponentEvents.DidAdd<ModelComponent> received: 1 (control: 1 expected, plus one per generated mesh)
```

## Cause (observed with SPI, not part of the reproduction)

`_USDKit_RealityKit` imports RealityFoundation's `Entity.isHidden` getter and setter, which aren't in the SDK. A probe that calls them through `dlsym` showed:

- Every `ModelEntity` that `USDStageComponent` generates has `isHidden == true`. Their `isEnabled` and `isActive` are true. The stage entity and its container entity aren't hidden.
- A control `ModelEntity` with `isHidden` set to `true` disappears from `performQuery` too.
- Setting `isHidden = false` on a generated mesh makes `performQuery` return it.
- The RealityView content's own `AnchorEntity` is also hidden.

So `isHidden` removes entities from queries and events without affecting rendering, and USDKit sets it on everything it generates.

Other behaviour seen while testing animated USD (time-sampled translate, points and visibility): entities keep their identity across time codes, transforms update in place, deforming points get a new `MeshResource`, and `visibility` maps to `isEnabled`. Also, `MeshResource.lowLevelMesh` returns a new wrapper object on every read.

## Feedback text (as filed)

> **USDKit: entities generated by USDStageComponent are missing from Scene.performQuery and send no ComponentEvents**
>
> On macOS 27.0.1 (26A434), the ModelEntities that USDStageComponent generates render and are reachable through `children`. But `scene.performQuery(EntityQuery(where: .has(ModelComponent.self)))` doesn't return any of them, and `ComponentEvents.DidAdd` doesn't fire for them. A control ModelEntity in the same scene is returned and sends the event. The attached package reproduces it with Apple frameworks only (`swift run USDKitQueryRepro`): 2 generated meshes, 0 returned by the query, 3 of 3 runs.
>
> The generated entities appear to be marked with the SPI `Entity.isHidden` (imported by _USDKit_RealityKit; it isn't in the SDK). Setting it on an ordinary entity removes it from queries too.
>
> Impact: a custom System that uses EntityQuery, the documented pattern, never sees USD content. Selection, outlines, and any per-entity behaviour have to walk `children` instead. There's also no public way to map a USD prim to the entity USDStageComponent generates for it (USDPlayer's MeshData has a primPath, but that path means building your own entities).
>
> Expected: generated entities are returned by queries and send component events like any other entity, or the documentation explains that they're excluded. Ideally there's also a public prim-path → entity lookup.
